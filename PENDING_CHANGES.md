# Pending changes

Requests logged here are not built yet. Say "build" to fold them into a new version
(version number goes up, CHANGELOG.md is updated, this list is cleared), and "push" to upload to GitHub.

Current released version: 0.2.0

1. Fix: container crash-loops with `EACCES: permission denied, mkdir '/data/cache'` when /data is a host folder (or volume) owned by root. Start the container as root, have an entrypoint fix ownership of /data and then drop to the `node` user; also print a clear message instead of a stack trace if the data folder is not writable.
2. Fix: every channel shows "Stream error (Exception)". Cause (reproduced): with web workers on (the default) the player fetches the relative stream URL inside a worker, where relative URLs can't be parsed ("Failed to parse URL from /stream/..."). Fix: build the stream URL as an absolute address in the page. Add a test that runs the real player with workers on.
3. Fix: with 6 or more streams playing, buttons stop working (Create admin does nothing, Multiviews loads forever) and tiles 7-9 never start. Cause (reproduced): browsers allow only 6 simultaneous plain-HTTP connections to one address, and every stream holds one open. Fix: carry the streams over WebSockets (no such limit; verified 9 at once alongside normal requests), with the same login/permission checks, keeping plain HTTP as an automatic fallback (for proxies that block WebSockets) and a Settings option. Add tests with 9 real-player streams plus API calls.
4. Nvidia Shield / Android TV app: a small APK (web view around the existing page) with a TV launcher icon, D-pad support and a first-run screen asking for the server address (remembered). Built by GitHub Actions on each release and attached to the release for sideloading (Downloader app). Known risk: AC-3/MP2 audio may be silent in the web view; a native-player version would be a later step. Depends on #3 (WebSocket streams).
5. Longer buffer (minutes). Today the Settings maximum is 15 s (hard cap 30 s in the app and server) and the relay keeps about 16 MB (10-20 s) per channel. Add: buffer choices up to 5 minutes; separate "start playing after" (short, so tiles don't wait minutes) from "keep up to" (long, rides out provider hiccups); server burst cap and relay memory sized by seconds (new RING_SECONDS setting plus a memory warning), per-channel and total memory limit so 9 channels can't exhaust the server.
6. Bug: Category dropdown is greyed out when there is only one provider. Cause (found in the code): with a single provider the picker shows that provider's name but leaves its internal selection empty, and categories only switch on when a provider is selected. Fix: treat a single provider as selected so its categories show; also make categories work when several providers are shown at once (merge by name), and build categories from channel category ids/name prefixes if a provider's own list is empty.
7. VOD (movies and series): browse and play the provider's VOD library (Xtream movie and series lists, seasons/episodes), with search and categories. Plays through a range-capable proxy into a single player tile (mp4 plays directly; mkv/HEVC/AC-3 may not play in the browser without server-side conversion, which would be a later option). Counts against the provider's connection limit while playing.
8. Local capture card as a channel. Add a "Local sources" provider type: the server runs ffmpeg on a capture device (V4L2 video, ALSA audio) and encodes to H.264/AAC MPEG-TS, which feeds the existing relay, so the capture shows up in the channel picker, multiviews and shared multiviews like any channel (and shares one encode between viewers). Settings per source: name, video device, audio device, resolution/frame rate, bitrate, optional hardware encoder (VAAPI/NVENC). Needs ffmpeg in the image and device passthrough in the stack (`devices: /dev/video0, /dev/snd`). Linux host only; HDCP-protected HDMI sources will not capture. Does not use a provider connection slot.
9. EPG (programme guide) view for channel selection: a guide grid in the channel picker (channels down the side, time across, now/next highlighted) using the provider's Xtream EPG data (short EPG per channel, or the provider's XMLTV file), cached on the server; pick a channel straight from the guide, show the current programme on tiles and in the picker, search by programme title. Works per provider; channels without EPG data show as blank. Remote-friendly (arrows to move, OK to add to the selected tile).
10. Channel picker remembers its place: when a channel is chosen (or the picker is closed), save the provider, category, search text, favorites toggle, how many rows were expanded and the scroll position / highlighted channel, and restore them the next time the picker opens, so you return to the same spot in the list. Kept per browser; a "Reset filters" button clears it.
