Long: Fullscreen button in the top-right controls; admin-only Fantasy Manager score pop-ups (headshot, rolling league totals, queue, delay, minimum points). New env FANTASY_URL and FANTASY_TOKEN; pop-ups stay off until both are set.

Port: 1234 (host = container; PORT=1234 in the image)   Exception: none. The register's target for iptv-multiview is 8043; not moved by this release.
Public hostname: unchanged by this release (see the homelab reference)        Needs Caddy route: no
New or changed env vars: FANTASY_URL (Fantasy Manager's LAN address and client port, e.g. http://<host>:<client port>) and FANTASY_TOKEN (read-only token from Fantasy Manager > Account > Multiview access). Both optional: empty or missing = pop-ups off. The values go only in the server .env (never in git, logs or chat). New API (admin only): GET /api/fantasy/status, GET /api/fantasy/stream (SSE), GET /api/fantasy/headshot/<id>.
Data: /data (accounts, providers, views, settings; small), /recordings (REC_DIR), /rewind (REWIND_DIR); the entrypoint chowns them to uid 1000 at start. Migration: none (nothing new is stored on the server; the pop-up settings are per device in the browser).
Resources: idle RAM and CPU not measured for this release. New: one idle HTTP connection to Fantasy Manager (only when both env values are set) and up to 300 headshots cached in memory (small). Bursty: ffmpeg for the shared screen / published streams (COMPOSE_MAX, default 2), 480p transcodes (TRANSCODE_MAX, default 2) and recordings; RING_MB (default 32 per open channel) and the rewind buffer on disk. Compose limits (cpus) are already set on the server.
Healthcheck: unchanged. GET /healthz on $PORT -> 200 {"status":"ok","version":"0.10.0"} (JSON, no login, nothing private); compose test: wget -qO- http://127.0.0.1:$${PORT}/healthz | grep -q '\"status\":\"ok\"' || exit 1 (see deploy/compose.yaml for the exact YAML), interval 30s, timeout 5s, retries 3, start_period 30s. On vm101 use: wget -S -qO- http://127.0.0.1:1234/healthz (no curl there).
Verify after deploy:

  2. wget -S -qO- http://127.0.0.1:1234/healthz returns {"status":"ok","version":"0.10.0"} with Content-Type application/json and the security headers.
  3. In the app (admin): tap a screen; the controls show a fullscreen button at the top right (after cast / mini player); it enters and leaves fullscreen. Not shown in the Android app.

If it says "Cannot reach..." check the address/port; "refused the token" = recreate the token in Fantasy Manager (Account > Multiview access). Without the two values it says "not set up on the server", which is expected.

Known issues: pop-ups cannot be earlier than Fantasy Manager's own score update (about 15-60 s behind Sleeper) and the Delay setting only adds time. Two UI tests ("admin turns logins on, publishes..." and "viewer with several multiviews...") fail in the sandbox browser run on 0.9.0 and 0.10.0 alike (CI does not run the browser suite). The bottom ticker (P-25) is not in this release. Server compose is the homelab repo's stacks/multiview-iptv/compose.yaml: add FANTASY_URL=${FANTASY_URL:-} and FANTASY_TOKEN=${FANTASY_TOKEN:-} under environment (see deploy/compose.yaml); an image-only update works without them and leaves the pop-ups off.
Backup tier: small/critical (include /data in Tier 1; no SQLite, JSON files, stop during copy to be safe). /recordings and /rewind are bulk (SnapRAID only; the rewind buffer is cleared at start).
