# Release v0.12.0
Update: later                    (now | later; now only when James said "build, push and update" for this release)
Image: mybadreligon/multiview-iptv:0.12.0   (also 0.12 and latest; built by the push-to-main release workflow, run https://github.com/jameshoffman7667/multiview-iptv/actions/runs/42539565932, all four jobs succeeded)
Short: Fantasy Manager connection set per admin
Long: Admins enter their own Fantasy Manager address and token in Settings; token encrypted in /data, LAN and Tailscale addresses only, connection open only while a page is open. FANTASY_URL and FANTASY_TOKEN removed.
Release commit: 2aada7a on main        Tag pushed from authoring session: no (the workflow created v0.12.0 with gh release create --target; release page has iptv-multiview.apk, 5.8 MB)
Type: minor
Port: 1234 (host = container; PORT=1234 in the image)   Exception: none. The register's target for iptv-multiview is 8043; not moved by this release.
Public hostname: unchanged by this release (see the homelab reference)        Needs Caddy route: no
New or changed env vars: none added. FANTASY_URL and FANTASY_TOKEN are removed from the compose files, .env.example and docs. Compose change on the server: only those two lines are deleted (this server never had them set; leaving them would be harmless, nothing reads them). .env.example: the two commented lines are gone. New API (admin only, 403 for others): GET/POST/DELETE /api/fantasy/config, POST /api/fantasy/test; /api/fantasy/status, /stream, /summary and /headshot/<id> now use the signed-in admin's own connection (404 until one is saved).
Data: /data (accounts, providers, views, settings; small), /recordings (REC_DIR), /rewind (REWIND_DIR); the entrypoint chowns them to uid 1000 at start. Data format: NEW files /data/fantasy.json (per admin: address, encrypted token, last 4) and /data/fantasy.key (random 32-byte AES key, mode 0600), both created only when an admin saves a connection; nothing else changes and nothing needs migrating. Keep fantasy.key in the /data backup: without it saved tokens cannot be read and must be typed again.
Resources: idle RAM and CPU not measured for this release. New: a connection and a small JSON poll per admin to Fantasy Manager, only while that admin has a page open (closed 60 s after the last page; last summary kept 60 s); none when nothing is saved. Bursty: ffmpeg for the shared screen / published streams (COMPOSE_MAX, default 2), 480p transcodes (TRANSCODE_MAX, default 2) and recordings; RING_MB (default 32 per open channel) and the rewind buffer on disk. Compose limits (cpus) are already set on the server.
Healthcheck: unchanged. GET /healthz on $PORT -> 200 {"status":"ok","version":"0.12.0"} (JSON, no login, nothing private); compose test: wget -qO- http://127.0.0.1:$${PORT}/healthz | grep -q '\"status\":\"ok\"' || exit 1 (see deploy/compose.yaml for the exact YAML), interval 30s, timeout 5s, retries 3, start_period 30s. On vm101 use: wget -S -qO- http://127.0.0.1:1234/healthz (no curl there).
Verify after deploy:
  1. docker inspect shows "healthy" within about a minute and the logs are clean (no stack traces; no repeated "Fantasy Manager" errors).
  2. wget -S -qO- http://127.0.0.1:1234/healthz returns {"status":"ok","version":"0.12.0"} with Content-Type application/json and the security headers.
  3. Manual step (once, per admin who wants pop-ups or the ticker): Settings > Fantasy Manager: enter the address (http://<Fantasy Manager LAN or Tailscale IP>:<its client port>) and the read-only token from Fantasy Manager > Account > Multiview access, press Test connection (expect "ok - connected to Fantasy Manager <version>"), then Save. After saving the field shows only "Token saved (ends xxxx)". Without it nothing contacts Fantasy Manager, which is expected.
  4. After saving: the pop-up and ticker options appear, the ticker bar shows along the bottom within a minute, and /data now holds fantasy.json and fantasy.key (ls -l: both mode 600). Non-admin accounts get 403 on /api/fantasy/config; a localhost or public address is refused with a message.
PWA: manifest, icons and install unchanged; service worker cache is mv-shell-0.12.0 (changes with the version). Layout: the UI suite checked the new Settings section; no layout change elsewhere. Cloudflare Access bypass for /manifest.webmanifest, /sw.js and /icons/*: needed (state done/not done is on the server side).
Docker build: not run locally (no Docker in the authoring session); CI ran npm test, built and pushed the image (amd64 + arm64) and compiled the Android APK (all four jobs succeeded). Address rules, encryption, admin-only routes, per-user isolation and idle closing were tested against a mock Fantasy Manager; the real Fantasy Manager 4.17.1 has NOT been tested, and the Android app was not run on a device.
Rollback: previous image tag 0.11.0 (pin whatever tag was running before this update); data restore needed? no (rolling back leaves fantasy.json and fantasy.key unused; 0.11.0 and earlier still need no Fantasy Manager lines)
Known issues: only admins can use Fantasy Manager (by design). Pop-ups and the ticker follow Fantasy Manager's own update (about 15-60 s behind Sleeper). League name colour is plain white (assumed). One UI test ("admin turns logins on, publishes...") fails in the sandbox browser run on 0.9.0 onward (CI does not run the browser suite).
Backup tier: small/critical (include /data in Tier 1; no SQLite, JSON files, stop during copy to be safe). /recordings and /rewind are bulk (SnapRAID only; the rewind buffer is cleared at start).
