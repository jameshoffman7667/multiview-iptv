Verify after deploy:
  1. docker inspect shows "healthy" within about a minute and the logs are clean (no stack traces; no repeated "Fantasy Manager" errors).
  2. wget -S -qO- http://127.0.0.1:1234/healthz returns {"status":"ok","version":"0.13.0"} with Content-Type application/json and the security headers.
  3. As an admin: Settings > Diagnostics opens a window with the screens and channels playing, and a server line (CPU, load, memory, event-loop delay, ffmpeg). Non-admins get 403 on /api/diag.
  4. With a channel playing press "Run 30 s test": it ends with a verdict and a report to copy. Interpreting it: provider = silence or reconnects from the provider; server = busy server; link = Wi-Fi or LAN to the device; device = dropped frames.
PWA: manifest, icons and install unchanged; service worker cache is mv-shell-0.13.0 (changes with the version). Layout: real-browser screenshot of the window at 1600x900 (the sandbox browser cannot play MPEG-TS, so the live rows were checked by tests with stand-in data). Cloudflare Access bypass for /manifest.webmanifest, /sw.js and /icons/*: needed (state done/not done is on the server side).
Docker build: not run locally (no Docker in the authoring session); CI ran npm test, built and pushed the image (amd64 + arm64) and compiled the Android APK (all four jobs succeeded). The server numbers were tested against a mock provider; the stall counting and verdict rules were tested with stand-in data, not against a real buffering session or the Android app.
Rollback: previous image tag 0.12.0 (pin whatever tag was running before this update); data restore needed? no
Known issues: the verdict thresholds are first guesses (silence over 2 s, event-loop delay over 100 ms, speed test under 3x the stream rate, over 2 % dropped frames) and may need tuning after real use. The speed test competes briefly with the video. Stall counts exist only for screens that were open while the window was used (kept 10 minutes). One UI test ("admin turns logins on, publishes...") fails in the sandbox browser run on 0.9.0 onward (CI does not run the browser suite).
Backup tier: small/critical (include /data in Tier 1; no SQLite, JSON files, stop during copy to be safe). /recordings and /rewind are bulk (SnapRAID only; the rewind buffer is cleared at start).
